# MindMirror 独立 Web 项目结构

## 依据与边界

依据用户提供的 CHI 研究初稿 第 3.2–3.4 节搭建。论文中的原系统使用 Coze 和 Doubao-1.5-pro-32k，通过结构化系统 Prompt 管理八天任务、CBT 工具选择、对话流程和温和的人设。本目录是独立 Web 实现，按正文描述建立对应流程。原系统 Prompt 附件尚未取得，不能声称与原 Agent 完全一致。

## 八天状态

| 阶段 | 论文任务 | Web 页面 |
|---|---|---|
| 第 1 天 | 解释想法—情绪—行为链；回顾社交媒体使用利弊；选择个人目标 | 引导式多轮对话 |
| 第 2–7 天 | 记录当天使用时长；识别负面情绪关键时刻；捕捉自动想法；使用 CBT 工具；共同形成新想法 | 每日反思、多轮对话、工具显示 |
| 第 8 天 | 回顾学习历程；复习 CBT 工具；总结与结束 | 总结页面；数据分析展示位预留 |

## 每日对话状态

`usage → event → thought → tool → belief`

工具由模型根据自动想法的内容选择，不等待固定的工具步骤。初稿第 3.3 节明确给出“证据探测器”和“可能性放大镜”：前者分别收集支持与反驳想法的证据，后者探索至少三种其他解释。访谈结果和讨论还写到“视角转换”：让用户设想如何理解处于同样情境的朋友，再把善意带回自己；也可以探索他人可能的视角。页面左侧显示本轮对话焦点、今日引导进度，以及工具是“建议尝试”还是“正在使用”。

## 模型接口与日期记录

服务端维护开始日期、每日对话、当前阶段与所用工具；以 Asia/Shanghai 日期自动计算第几天。同一浏览器通过匿名 Cookie 恢复记录。模型每轮接收当前阶段、历史摘录和 CBT 资料，先回应用户具体情境与感受，再视需要引导或提供一个可尝试的 CBT 方法。当前 DeepSeek 调用开启低强度思考，输出仍是自然对话，不展示内部推理。用户提出即时危险或自伤时退出常规流程，转为支持提示。真实模型 Key 只保存在服务端。

用户可随时结束今天，结束后仍可选择继续当天对话。系统不限制固定轮次；第 1 天在轻松介绍、梳理利弊并由用户自己确定小目标后收束，第 2—7 天在完成一次反思后收束。论文初稿没有指定固定轮数。

每轮由同一 DeepSeek 模型承担三个独立角色：情境理解角色概括具体经历与诉求，CBT 策略角色从资料库选择一项工具和下一小步，两者并行调用；对话整合角色读取两份分析和原始对话，生成唯一的用户可见回复并决定焦点、工具状态及阶段推进。前两份分析可能失败，整合角色仍须依据用户原话完成回复。这是代码编排的多角色 Agent，不依赖 Coze 或 LangChain；每轮最多产生三次模型调用，令免费额度消耗和等待时间增加。

## 页面与数据

- `index.html`：独立项目的首页、旅程状态、对话区与分析占位。
- `styles.css`：桌面与移动端布局。
- `app.js`：前端路由、会话显示和服务端请求。
- `server.mjs`：按日期恢复会话、保存消息、通过火山方舟 Chat API 调用 DeepSeek 并约束阶段推进。
- `knowledge.json`：带来源的 CBT 工具资料，由服务端加入每轮模型上下文。
- 分析页后续展示论文中确有依据的研究方法与结果，先不在交互中伪造个人趋势或疗效数据。
